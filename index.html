Data (Part A · 25 Marks)

From messy exports to a modelling table you can trust.

Reusable functions clean_shipments and build_features in src/shipment_prep.py sanitize text glitches, scanner faults, and missing cells before any model sees the data.

  1. Remove exact duplicates24 duplicate rows dropped from 1,224 raw records, leaving 1,200 unique shipments across 24 hubs.
  2. Normalize service typeLeading/trailing whitespace stripped and title-cased, collapsing 12 messy spellings into 3 (Express, Standard, Economy).
  3. Fill payment mode18 missing payment cells replaced with the clean placeholder "Unknown".
  4. Parse declared valueRupee signs (₹) and commas stripped into declared_value_inr, then natural-log transformed (log_declared_value).
  5. Catch 999 kg scanner faults5 sentinel weights above 100 kg (network limit 40 kg) converted to missing prior to median imputation.
  6. Impute with training medians36 missing distances (314.95 km), 29 missing weights (1.83 kg), and 12 missing values (INR 1,121.50) imputed cleanly.

Pipeline (100% Offline & Reproducible)

Seven commands. Everything regenerates.

Every script runs top-to-bottom from a clean clone on the main branch using pinned open-source libraries.

bash — delhivery-delay-pipeline (main)
pip install -r requirements.txt
python generate_data.py          # writes data/hubs.csv (24), raw_shipments.csv (1224), new_shipments.csv (48)
python part_a_clean_eda.py       # Data (Part A): cleans data, writes modelling_table.csv (1200)
python part_b_regression.py      # Hours (Part B): trains delivery-hours models (Test R² = 0.949)
python part_c_classification.py  # Alerts (Part C): selects top 7 features, sets 0.50 threshold
python part_d_segments.py        # Hubs (Part D): K-Means (K=3) clustering & 4 tier mismatches
python package_model.py          # packages models/delay_model.pkl & verifies 0.0 reload diff
python predict_delay.py          # scores 48 new parcels into outputs/new_shipment_actions.csv
